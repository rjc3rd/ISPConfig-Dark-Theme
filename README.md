# ISPConfig Dark Theme

A dark theme for the ISPConfig 3 control panel. Neutral greys, flat two-tone surfaces, and every color in the panel's stylesheets covered, so you don't run into leftover white boxes on pages you rarely open.

Built for **ISPConfig 3.3.2p1**. It's an unofficial theme, not affiliated with ISPConfig.

Discussion and feedback: [HowtoForge forum thread](https://forum.howtoforge.com/threads/dark-theme-for-ispconfig-3-3-2p1-open-source.95383/)

## Install

On the ISPConfig server, as root:

```bash
git clone https://github.com/rjc3rd/ISPConfig-Dark-Theme.git /tmp/ispconfig-dark
cp -r /tmp/ispconfig-dark/dark /usr/local/ispconfig/interface/web/themes/dark
chown -R ispconfig:ispconfig /usr/local/ispconfig/interface/web/themes/dark
chmod -R 750 /usr/local/ispconfig/interface/web/themes/dark
```

Then choose the theme per user:

- Admin users: **System > CP Users > (user) > Theme**
- Clients: **Client > (client) > Address > Theme**

Log out and back in. The theme is applied at login.

## Optional: dark login page that follows the OS

ISPConfig always renders the login page (and the 2FA and forced password change pages) with the `default` theme, whatever theme a user has picked. This patch adds the dark stylesheets to the default theme's login template, only when the browser or OS prefers dark:

```bash
cd /usr/local/ispconfig/interface/web/themes/default
patch -p1 < /tmp/ispconfig-dark/patches/default-login-auto-dark.patch
```

It edits a stock ISPConfig file, so an ISPConfig update overwrites it. Re-apply it after each update.

## After an ISPConfig update

ISPConfig only loads a custom theme when `themes/dark/ispconfig_version` matches the installed version. After an update the panel quietly falls back to the default theme until it does.

Use the release of this theme matching your ISPConfig version. If there isn't one yet, you can set the file to your version:

```bash
grep ISPC_APP_VERSION /usr/local/ispconfig/interface/lib/config.inc.php
echo 3.3.2p1 > /usr/local/ispconfig/interface/web/themes/dark/ispconfig_version
```

This works as long as the update didn't change the default theme's templates or JavaScript. If it did, the dark copy is out of date until the theme is updated.

## How it works

- `dark/` is ISPConfig's default theme, with two extra stylesheet links in `main.tpl.htm` and `main_login.tpl.htm`, plus a script tag for `dark-charts.js` in `main.tpl.htm`.
- `dark.css` is generated by `tools/build-dark.py`. It reads every stylesheet the panel loads, in the same order, and writes a matching rule with dark colors for every color setting. Selectors and load order stay the same, so nothing in the original CSS gets missed. Colored buttons keep their hue and are darkened until white text on them is readable.
- `dark-extra.css` handles what isn't in any stylesheet: colors hard-coded into ISPConfig's module templates, the logo, the navigation tabs and the list tables.
- `dark-charts.js` sets dark text, grid and legend colors for the dashboard and monitor charts, which draw on a canvas that CSS can't reach.

To change the palette, edit the values at the top of `tools/build-dark.py` and run it (Python 3, no dependencies):

```bash
tools/build-dark.py --report
```
